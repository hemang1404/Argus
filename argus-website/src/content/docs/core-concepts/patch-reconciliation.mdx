---
title: Patch Reconciliation
description: The five matching tiers, what each accepts, and why ambiguity results in refusal.
---

Patch reconciliation answers one question: given a proposed search block, where —
if anywhere — does it belong in the current file? Argus escalates through five
tiers and accepts a result only when it is unambiguous and syntactically valid.

## The patch format

Argus accepts search/replace blocks with three or more marker characters:

```text title="Search/replace block"
<<<<<<< SEARCH src/calculator.py
def add(a, b):
    return a - b
=======
def add(a, b):
    return a + b
>>>>>>> REPLACE
```

It also accepts unified diff hunks and converts each hunk into a search/replace
pair. Multiple blocks may be parsed from one response, but the runtime applies a
**single-file** patch; a multi-file patch set is refused rather than partially
applied.

## The ladder

| Tier | Strategy | Accepts when | Default |
| --- | --- | --- | --- |
| 1 | Exact match | The search text occurs verbatim at a line or token boundary | Active |
| 2 | Whitespace normalization | Whole lines match after normalizing indentation and trailing whitespace | Active |
| 3 | Token-equal | Same identifier, operator, number and string tokens; only whitespace and comments differ; unique | Active (`enable_tier3`) |
| 4 | Anchor matching | Prefix/suffix anchors agree and the span similarity ≥ 0.85 | Disabled |
| 5 | Safe refusal | No unambiguous match exists | Terminal |

### Tier 1 — Exact matching

The search block must occur verbatim in the source, aligned to a line or token
boundary. It is never accepted inside a longer identifier, or inside a comment or
string literal that it does not fully cover, and a whole-line match is preferred
over a fragment. A search that could match more than one place is refused. This
is the safest and most common success case: the model reproduced the file
accurately.

### Tier 2 — Whitespace and indentation normalization

Tier 2 reconciles leading indentation and trailing line whitespace on whole
lines. It does not collapse internal spacing inside expressions and does not
reorder lines. A block that matches only after indentation normalization is
accepted, then still has to pass the syntactic gate.

This tier exists because indentation drift is the single most common reason a
correct LLM edit is discarded by conventional patch tools.

### Tier 3 — Token-equal matching

Tier 3 tolerates formatting drift, not content drift. A region is accepted only if
its identifier, operator, number and string tokens are **identical** to the search
block's, so the two differ only in whitespace and comments, the region is unique,
and its character-level similarity is above a floor (`similarity_threshold`,
default `0.82`). A near miss that changes a token is refused:

| Search block | Region in the file | Result |
| --- | --- | --- |
| `if x <  limit:` | `if x < limit:` | Applied (whitespace only) |
| `if x < limit:` | `if x <= limit:` | Refused |
| `return a` | `return b` | Refused |
| `retries = 3` | `retries = 5` | Refused |

Disable Tier 3 entirely with `enable_tier3=False` in `ArgusConfig` or the engine.

### Tier 4 — Anchor-based matching

Tier 4 uses unchanged code before and after the drifted interior as anchors. It
is implemented but **disabled by default**. No benefit has been measured for it
(maintainer-reported: no extra solves in a small pilot and in offline replays;
never run on the 99-task development set; see [Research](/project/research/)),
and its failure modes need independent review. Enable it explicitly:

```bash title="Shell"
argus run --test "pytest tests/test_calculator.py" --enable-tier4
```

The flag is also available as `--allow-tier4`. Even when enabled, acceptance
requires the syntactic gate and the anchor similarity threshold.

### Tier 5 — Safe refusal

Tier 5 is not an algorithm. It is the outcome when no active tier produces a
unique, valid result. The file is left unchanged and the attempt is recorded as a
failure. The run may try again with new context; it will never apply a
lower-confidence match just to make progress.

## Syntax validation (a syntactic gate only)

For `.py`, `.pyi` and `.pyw` files (case-insensitive), the final patched file is
parsed with `ast.parse` and compiled with `compile()`, which also catches
module-level `return`, stray `break` and similar errors. The check is on the
complete file, so an edit that closes a bracket in the wrong place is caught even
if the fragment looks plausible. When a response has several blocks, only the final
state is gated.

This is a **syntactic** check. The result records `level = "syntactic"`. It says
the file parses, not that the change is correct; only your test command can say
anything about behaviour, and even that is test-relative.

The gate is Python-only. Non-Python files are outside the supported scope for
recovery, and a patch to them is not verified by this mechanism.

## Encodings and line endings

Files are decoded strictly (UTF-8, a byte-order mark, or a PEP 263 coding
comment). A file that cannot be decoded is refused (`UNSUPPORTED_ENCODING`)
instead of being rewritten with replacement characters. Matching happens on
normalized line endings, and the original endings (LF, CRLF, CR or a mix) and BOM
are restored when the file is written.

## Malformed responses

The SEARCH/REPLACE parser reads one line at a time. An empty REPLACE section is a
valid deletion. A truncated or malformed block is reported back to the model and
nothing from that response is applied, rather than applying a damaged fragment. An
edit whose replacement text is already present is reported as already applied.

## Where the thresholds live

The tier settings are fields on `ArgusConfig` and arguments to
`ResilientPatchEngine`: `similarity_threshold` (default `0.82`, the Tier 3
similarity floor), `enable_tier3` (default `true`) and `enable_tier4` (default
`false`). The CLI exposes Tier 4 through `--enable-tier4`; the tier settings are
not read from `argus.yaml`, so a YAML value will not change them. If a candidate
is refused, improve the context or the model output rather than lowering
thresholds.

Programmatic callers can construct the engine directly:

```python title="Using the engine"
from argus.patch.fuzzy_engine import ResilientPatchEngine
from argus.patch.parser import PatchBlock

source = open("src/calculator.py", encoding="utf-8").read()
engine = ResilientPatchEngine()
block = PatchBlock(search_text="    return a - b", replace_text="    return a + b")
result = engine.apply_patch(source, block, filename="src/calculator.py")
print(result.success, result.tier_used, result.details)
# result.patched_code holds the new text on success; several blocks: engine.apply_blocks(source, [b1, b2])
```

See the [Python API](/interfaces/python-api/) page for the larger recovery
interface.
