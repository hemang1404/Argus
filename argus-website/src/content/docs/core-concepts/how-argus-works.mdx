Argus is a pipeline with a hard stop at the end. Understanding the pieces makes
the failure modes legible.

## Subsystems

The controller, workspace manager, test runner, patch parser and engine, provider
adapters, candidate store, applier and localizer are listed with their modules on
the [Architecture](/project/architecture/) page.

The same controller is used by the CLI, the TUI, the MCP server, and direct
Python calls. Those surfaces are adapters, not alternative implementations.

## Data flow

```text title="Recovery data flow"
your repository
      │
      │  temporary copy
      ▼
ephemeral workspace ──► test command ──► failure + traceback
                                              │
                                              ▼
                                   target file + failure context
                                              │
                                              ▼
                                     provider adapter
                                              │
                                       proposed patch
                                              │
                                              ▼
                     parser ──► tier ladder ──► AST gate
                                              │
                                        applied content
                                              │
                                              ▼
                             test command rerun in workspace
                                              │
                                   pass ──────┴────── fail
                                     │                 │
                                     ▼                 ▼
                            candidate artifact   next attempt
                                     │           (max 3 turns)
                                     ▼
                          human review + approval
                                     │
                                     ▼
                        atomic write to your file
```

## Bounded computation

Every stage has a ceiling. These defaults come from `ArgusConfig`:

| Bound | Default | Where it applies |
| --- | --- | --- |
| Recovery attempts | 3 | `max_attempts` (ceiling `MAX_ATTEMPTS_CEILING`) |
| Test timeout | 30 s | `test_timeout_seconds` |
| Repository test timeout | 180 s | `repo_test_timeout_seconds` |
| Provider request timeout | 45 s | `provider_timeout_seconds` |
| Task deadline | 300 s | `task_deadline_seconds` |
| Captured output | 4 MB | `BoundedOutputCollector` |
| Inference budget | $0.030 | `budget_limit_usd` (`DEFAULT_BUDGET_USD`) |
| Completion tokens | 2500 | `max_tokens` |

Timeouts terminate the whole process tree — `taskkill /F /T` on Windows,
`os.killpg` on POSIX — not just the parent process.

## Reconciliation is not generation

The model proposes a change. Argus decides whether that change can be located
unambiguously in the current file and whether the result is syntactically valid.
This separation is why a bad generation fails closed rather than corrupting a
neighbouring function.

The ladder is progressive:

1. **Exact.** The search block occurs verbatim at a line or token boundary.
2. **Normalized.** Whole lines match after indentation and trailing whitespace are
   normalized.
3. **Token-equal.** A unique region with the same identifier, operator, number and
   string tokens, differing only in whitespace and comments.
4. **Anchored.** Prefix and suffix anchors, only when explicitly enabled.
5. **Refusal.** No modification.

Every accepted result must pass the syntactic gate (`ast.parse` and `compile` of
the full file) before it is tried. That gate says the file parses, not that it is
right. See [Patch reconciliation](/core-concepts/patch-reconciliation/) for the
rules.

## Verification is not approval

A passing test shows only that the candidate satisfies the test command you
supplied. Verification is automatic, approval is an explicit human action, and
application re-checks everything before an atomic write. See
[Validation and approval](/core-concepts/validation-and-approval/).

## Invariants

- **Working-tree invariance.** Attempts run in a temporary copy, outside the live
  tree. See [Workspace isolation](/core-concepts/workspace-isolation/).
- **Fail closed.** If a provider, a model price, requested isolation or
  authentication is unavailable, execution stops instead of falling back.
- **Bounded work.** Turns, time, output, and spend all have ceilings.
- **Provenance and no silent apply.** A candidate records what produced it, and
  `argus run` never applies one on its own.

The [security model](/project/security-model/) covers the guarantees and their
limits.

<Aside type="caution" title="Scope today">
Reconciliation and AST verification are implemented for Python source files and
single-file patches. Multi-file patch sets are rejected. Non-Python recovery is a
roadmap item, not a current capability.
</Aside>
