Argus has three configuration layers: per-run CLI flags (or API/MCP arguments), a
project policy file, and the stored provider record. There is no global mutable
config service.

## Policy discovery

The repository being repaired is untrusted input, so its policy file is
**tighten-only**. `ArgusConfig.apply_project_policy()` looks in the **workspace
root** (not the current directory) for the first existing file among:

```text
argus.yaml
argus.yml
.argus.yaml
.argus.yml
```

If none exists, it reads `[tool.argus]` from `pyproject.toml`.

```yaml title="argus.yaml"
max_attempts: 3
budget_limit_usd: 0.05
test_timeout_seconds: 45
model: qwen2.5-coder:7b
reasoning_effort: medium
```

```toml title="pyproject.toml"
[tool.argus]
max_attempts = 3
budget_limit_usd = 0.05
test_timeout_seconds = 45
model = "qwen2.5-coder:7b"
```

### Recognized keys

| Key | Type | Effect |
| --- | --- | --- |
| `max_attempts` | integer | Recovery turns |
| `budget_limit_usd` | float | Spend ceiling in USD |
| `test_timeout_seconds` | integer | Reproduction timeout |
| `escalation_enabled` | boolean | `false` turns model escalation off (it cannot turn it on) |
| `reasoning_effort` | string | Default reasoning effort, if the caller did not set one |

For `max_attempts`, `budget_limit_usd` and `test_timeout_seconds` a file can only
**lower** the caller's value; a higher value is ignored. The keys `model`,
`small_model`, `large_model` and `provider` are **ignored**: a repository cannot
choose your model or provider (use `--provider`/`--model`). Every tightened,
ignored or unparsable entry is reported in the run output and in
`outcome.config_notes`. The policy is applied to a per-run copy of the config, so
it never leaks into the next run.

Other fields on `ArgusConfig` (`similarity_threshold`, `enable_tier3`,
`enable_tier4`, snapshot options, `model_prices`) are not read from files. Set
them through the Python API; use `--enable-tier4` on the CLI for Tier 4.

## Runtime defaults

| Field | Default | Meaning |
| --- | --- | --- |
| `max_attempts` | `3` | Recovery turns (ceiling `MAX_ATTEMPTS_CEILING`, 10) |
| `test_timeout_seconds` | `30` | Reproduction timeout |
| `repo_test_timeout_seconds` | `180` | Repository-scale test timeout |
| `provider_timeout_seconds` | `45.0` | Provider request timeout |
| `rate_limit_backoff_max_seconds` | `60.0` | Maximum backoff |
| `task_deadline_seconds` | `300.0` | Whole-run deadline |
| `max_tokens` | `2500` | Completion ceiling |
| `temperature` | `0.0` | Sampling temperature |
| `budget_limit_usd` | `0.030` | Spend ceiling (the CLI, API, TUI and MCP share `DEFAULT_BUDGET_USD`; MCP caps agent input at `0.25`) |
| `similarity_threshold` | `0.82` | Tier 3 similarity floor |
| `enable_tier3` | `true` | Token-equal matching |
| `enable_tier4` | `false` | Experimental anchor matching |
| `escalation_enabled` | `true` | Cheap-first ladder when no model is named |
| `small_model` / `large_model` | unset | Explicit two-rung ladder |
| `model_prices` | `{}` | USD per 1M tokens for models not in the built-in table |
| `snapshot_exclude` | `[]` | Extra root-level names to leave out of the workspace copy |
| `snapshot_respect_gitignore` | `true` | Copy only tracked and untracked-not-ignored files in Git projects |
| `snapshot_max_bytes` | 2 GiB | Fail fast above this snapshot size |
| `use_container_runner` | `false` | Container evaluation harness |
| `require_container_isolation` | `false` | Fail closed if containment is unavailable |

## Provider selection

The runtime resolves a provider in this order:

1. an explicit `provider_config` passed to `ArgusConfig`;
2. the stored active provider;
3. `ARGUS_PROVIDER`.

A credential alone never selects a provider. An unknown provider name is a
`CONFIG_ERROR`. The model is resolved separately and a model you name always wins
(see [Provider configuration](/guides/provider-configuration/)). When `--provider auto` is requested,
Argus prefers the stored active provider and then a detected Antigravity host CLI.
When no provider resolves, the run ends with `CONFIG_ERROR`.

Provider credentials are stored separately from policy. See
[Provider configuration](/guides/provider-configuration/).

## TUI policy

The TUI has a policy modal (`Tab` on the startup screen) with tier, budget,
attempt, and model controls. It persists a `policy.json` in the Argus
configuration directory, and subsequent TUI sessions load it at startup. The CLI
does not read `policy.json`; its flags and the tighten-only `argus.yaml` remain
authoritative.

## Configuration directory

Provider records and TUI policy live in the platform configuration directory:

| Platform | Location |
| --- | --- |
| Windows | `%APPDATA%\argus` |
| macOS / Linux | `$XDG_CONFIG_HOME/argus` or `~/.config/argus` |

Set `ARGUS_CONFIG_DIR` to override it. Keys are held in the OS keyring when
available (service name overridable with `ARGUS_KEYRING_SERVICE`), with a 0600
fallback file (`secrets.json`). The candidate signing key
(`artifact_signing.key`) is stored here too; Argus refuses a location inside the
workspace.

## Precedence summary

For most settings:

```text
caller (CLI flag, API/MCP argument) → project policy file (tighten-only)
  → dataclass default
```

Environment variables supply credentials and, as a last resort, the provider
name; they never override an explicit flag.

For providers:

```text
explicit provider_config → stored active provider → ARGUS_PROVIDER
```

For keys:

```text
OS keyring → provider environment variable → opt-in .env → ARGUS_API_KEY (custom only)
```

## Validation

`ArgusConfig.validate()` reports missing credentials for key-requiring providers,
unknown providers, and every model on the ladder that has no known price; any of
these ends the run with `CONFIG_ERROR` before a call is made. `argus doctor`
exposes the practical version of this check, including a live connectivity request
(billable). Groq configuration raises at construction time.
