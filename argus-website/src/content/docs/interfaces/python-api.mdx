Argus is a Python package first. The CLI, TUI, and MCP server are adapters over
the same runtime. The public entry points below are suitable for scripted
evaluation and integration.

<Aside type="note" title="Stability">
These are the current internal APIs of a pre-release project. Import paths and
signatures may change before a stable release. Pin a commit if reproducibility
matters for your evaluation.
</Aside>

## Run a recovery

```python title="recover.py"
from pathlib import Path

from argus.config import ArgusConfig
from argus.runtime.controller import RecoveryController

config = ArgusConfig(
    max_attempts=3,
    budget_limit_usd=0.03,
    test_timeout_seconds=30,
)

controller = RecoveryController(config=config)
outcome = controller.run(
    test_command="pytest tests/test_calculator.py",
    target_file="src/calculator.py",  # omit to auto-localize
    workspace_root=Path.cwd(),
)

print(outcome.status)
print(outcome.run_id)
print(outcome.verified)
print(outcome.unified_diff)
```

`RecoveryController.run()` accepts:

| Argument | Meaning |
| --- | --- |
| `target_file` | Source file to repair; optional |
| `test_command` | Reproduction command; required in practice |
| `test_file` | Optional test file to copy into the workspace |
| `workspace_root` | Project root. If omitted, it is inferred from the target file's directory; a target outside an explicit root is refused |
| `on_attempt_start` | Callback `(attempt, max_attempts)` |
| `on_attempt_end` | Callback receiving an `AttemptRecord` |
| `event_emitter` | JSON Lines emitter for machine-readable progress |
| `cancel_event` | Cooperative cancellation handle |

## Outcome

`RecoveryOutcome` carries the result of the run. The fields most consumers need:

| Field | Type | Meaning |
| --- | --- | --- |
| `status` | `str` | `SUCCESS`, `ALREADY_PASSING`, `FAILED_MAX_ATTEMPTS`, and so on |
| `verified` | `bool` | The reproduction passed for the candidate |
| `run_id` | `str` | Candidate identifier, when one was created (empty otherwise) |
| `target_file` | `str \| None` | Localized or explicit target |
| `unified_diff` | `str` | Reviewable diff |
| `total_attempts` | `int` | Attempts consumed |
| `total_cost_usd` | `float` | Measured inference spend |
| `total_duration_ms` | `float` | Wall-clock duration |
| `diagnostics` | `str` | Failure output for unsuccessful runs |
| `message` | `str` | Human-readable summary |
| `changed_files` | `list[str]` | Files modified inside the workspace |
| `effort_used` | `str \| None` | Adaptive routing decision |
| `routing_reasons` | `list[str]` | Why that effort and which model ladder (`model_ladder=...`) were chosen |
| `config_notes` | `list[str]` | Project-policy notes: limits tightened, keys ignored, parse errors |
| `tier_used` | `int \| None` | Patch (SEARCH/REPLACE matcher) tier that applied the accepted edit; never the model tier |
| `model_tier` | `int \| None` | Model-ladder tier (1 = cheap ... 3 = strong) of the final attempt; each `AttemptRecord` has both fields |

A `SUCCESS` outcome is the only state that produces an applyable candidate. Do
not infer applicability from `verified` alone; approval is still required.
`verified` means the supplied test command passed in the temporary copy. It is
neither a syntactic nor a semantic claim about the patch.

## Configuration

`ArgusConfig` is a dataclass. Commonly adjusted fields:

```python title="Bounds and policy"
config = ArgusConfig(
    provider="ollama",             # or pass provider_config
    model="qwen2.5-coder:7b",
    max_attempts=3,
    test_timeout_seconds=30,
    provider_timeout_seconds=45.0,
    task_deadline_seconds=300.0,
    budget_limit_usd=0.03,
    similarity_threshold=0.82,   # Tier 3 similarity floor
    enable_tier3=True,           # token-equal matching
    enable_tier4=False,          # experimental, off by default
    temperature=0.0,
    # model_prices={"my-model": ModelCost(input_cost_per_m=0.5, output_cost_per_m=1.5)},
    # snapshot_exclude=["big_dir"], snapshot_max_bytes=2 * 1024**3,
)
```

Model rules: a `model` you pass wins over the stored provider's default and is the
only model sent (no escalation). With no model, a provider that has a documented
ladder (`openai`, `deepseek`, `gemini`, `antigravity`) and `escalation_enabled`
uses the cheap model for attempts 1-2 and the stronger one for attempt 3 (the
CLI and MCP server always send the stored provider's model, so this applies to
library use only);
`small_model`/`large_model` set an explicit two-rung ladder; any other provider
uses its default model. `"argus/auto"` means "no model".

When `provider_config` is supplied, its name is used. When neither is supplied, the
stored active provider is used, then `ARGUS_PROVIDER`. A credential alone never
selects a provider. A model with no price in
the built-in table or `model_prices` is refused (`CONFIG_ERROR`) unless the
provider is local or host-native.

The workspace's project policy file can only tighten `max_attempts`,
`budget_limit_usd` and `test_timeout_seconds` (and turn escalation off); it is
applied to a per-run copy of the config and reported in `outcome.config_notes`.

## Candidate store and applier

```python title="Review and apply"
from argus.runtime.candidate import AuthoritativePatchApplier, CandidateArtifactStore

metadata, path = CandidateArtifactStore.load_candidate(
    run_id=outcome.run_id,
    workspace_root=Path.cwd(),
)
diff = CandidateArtifactStore.get_candidate_diff(
    run_id=outcome.run_id,
    workspace_root=Path.cwd(),
)

CandidateArtifactStore.set_approval(
    run_id=outcome.run_id,
    approved=True,
    workspace_root=Path.cwd(),
    approved_by="interactive:script",
    approval_source="python-api",
)

result = AuthoritativePatchApplier.apply(
    run_id=outcome.run_id,
    workspace_root=Path.cwd(),
    require_approval=True,
)
print(result.success, result.error_code, result.message)
```

Candidate-store calls raise `CandidateApplicationError` subclasses for a malformed
run ID (`INVALID_RUN_ID`) or unsigned or edited metadata
(`CANDIDATE_SIGNATURE_INVALID`).

The applier returns a result object rather than raising for ordinary refusals:
`success`, `message`, `error_code`, `run_id`, `target_file`, and `applied_at`.
Handle `success == False` explicitly.

## Patch engine directly

For experiments that separate reconciliation from execution:

```python title="Reconcile one file"
from argus.patch.fuzzy_engine import ResilientPatchEngine
from argus.patch.parser import PatchBlock

source = open("src/calculator.py", encoding="utf-8").read()
engine = ResilientPatchEngine(enable_tier3=True, enable_tier4=False)
result = engine.apply_patch(
    source,  # the file's text, not a path
    PatchBlock(search_text="    return a - b", replace_text="    return a + b"),
    filename="src/calculator.py",
)
print(result.success, result.tier_used, result.details)
# On success result.patched_code holds the new text. For several blocks, use
# engine.apply_blocks(source, [block1, block2]): the syntactic gate runs once, on
# the final state.
```

The engine runs the syntactic gate (`ast.parse` and `compile`) on the full file
before returning success; the result's `ast_result.level` is `"syntactic"`. It
refuses unsupported (non-Python) targets by name.

## Evaluation harnesses

Use the controller rather than shelling out to the CLI when measuring latency,
cost, or attempts. The CLI adds formatting and process startup overhead that does
not belong in an experiment. The runner for the published research experiments is
not part of the supported API. See [Research and benchmarks](/project/research/).

A complete, offline, runnable example (stub provider, throw-away project) is in
`examples/quickstart_recovery.py` in the repository.
